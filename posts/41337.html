五、性能调度

Python 提供了多进程池的支持，主要是为了解决全局解释器锁（GIL）的问题，因为 Python 的 GIL 限制了多线程的并行执行，特别是在 CPU 密集型任务中。为了绕过 GIL，Python 提供了 multiprocessing 模块，允许开发者通过多进程来实现真正的并行计算，进程池（multiprocessing.Pool）则简化了多进程的管理。

与此不同，Java 在设计时并没有提供类似进程池的支持。Java 的并发模型更侧重于多线程，而不是多进程。Java 的线程管理通过 ExecutorService 来高效管理线程池，并利用操作系统线程实现真正的并行，尤其是对于 I/O 密集型任务。由于 Java 不受 GIL 的限制，它在多线程方面比 Python 更为高效，对于 CPU 密集型任务，线程池通常已经足够。

对于需要多进程的场景，Java 依赖 ProcessBuilder 来启动和管理外部进程。虽然 Java 本身没有类似 Python 进程池的内建支持，但它提供了其他方法来处理多进程任务，并且通过线程池已能高效地处理并发任务。因此，Java 在并发编程上更多依赖线程池，而 Python 则通过多进程池来解决 GIL 带来的问题。

1 多线程概述

进程：

是指一个内存中运行的应用程序，每个进程都有一个独立的内存空间

线程：

  • 是进程中的一个执行路径，共享一个内存空间，线程之间可以自由切换，并发执行. 一个进程最少有一个线程
  • 线程实际上是在进程基础之上的进一步划分，一个进程启动之后，里面的若干执行路径又可以划分成若干个线程

2 多线程的实现

2.1 继承 Thread 类

2.1.1 Thread 类概述

Thread 是 Java 中用来创建和管理线程的类。通过继承 Thread 类，可以创建新的线程并重写 run() 方法，来定义线程执行的任务。

构造方法：
  • Thread()：创建一个新线程，默认没有名称。
  • Thread(String name)：创建一个线程并设置其名称。
  • Thread(Runnable target)：创建一个线程，并为其指定一个 Runnable 任务。
  • Thread(Runnable target, String name)：创建一个线程，指定任务和线程名称。
常用方法：
方法名称描述
long getId()返回当前线程的唯一标识符
String getName()返回当前线程的名称
void start()启动线程，调用线程的 run() 方法
void stop()已过时，停止线程的执行。应该通过标志位来控制线程的结束
static void sleep(long millis)使当前线程休眠指定的毫秒数
static void sleep(long millis, int nanos)使当前线程休眠指定的毫秒数加上纳秒数
void setDaemon(boolean on)设置线程为守护线程，守护线程在所有用户线程结束时自动终止
void interrupt()中断线程的执行
boolean isAlive()判断线程是否处于活动状态
Thread.State getState()获取当前线程的状态
void join()等待当前线程终止
void join(long millis)等待当前线程终止，最多等待指定的时间
static Thread currentThread()获取当前正在执行的线程对象

注意： 不推荐使用 Thread.stop()，因为它不安全，可能会导致线程状态不一致。

2.2 实现 Runnable 接口

2.2.1 Runnable 接口概述

与继承 Thread 类不同，Runnable 接口定义了一个 run() 方法，通过实现 Runnable 接口并传入 Thread 对象，可以使得线程执行 run() 中定义的任务。该方法更灵活，适合多个线程共享任务。

示例代码：实现 Runnable 接口

优点：

  • Runnable 接口适合多个线程共享同一个任务。
  • 可以避免继承 Thread 时的单继承限制。
  • 任务与线程分离，增加了代码的灵活性和可维护性。

2.3 实现对比：继承 Thread vs 实现 Runnable

  1. 任务与线程分离：

    • 继承 Thread：任务和线程绑定在一起，不够灵活。
    • 实现 Runnable：任务与线程解耦，更灵活。

  2. 单继承问题：

    • 继承 Thread：Java 只支持单继承，无法再继承其他类。
    • 实现 Runnable：可以同时继承其他类，避免单继承的限制。

  3. 适用于多个线程共享任务：

    • 继承 Thread：每个线程需要创建一个新的 Thread 实例，资源利用率低。
    • 实现 Runnable：多个线程可以共享同一个 Runnable 实例，资源利用率高。

  • 都是接口。
  • 都用于执行多线程任务。
  • 都需要使用 Thread.start() 启动线程。

特性RunnableCallable
返回值无返回值可以返回执行结果（通过 call() 方法）。

任务执行run() 方法没有返回值，任务执行后直接结束。call() 方法可以返回执行结果，适合需要返回值的任务。

  • 返回值支持：Callable 允许返回任务执行结果，适用于需要结果的场景。
  • 异常支持：Callable 的 call() 方法可以抛出异常，可以处理任务执行中的异常，Runnable 的 run() 方法不支持。

7 线程池 Executors

当并发的线程数量很多且每个线程执行的任务较短时，频繁创建和销毁线程会大大降低系统效率。线程池提供了一种解决方案，它是一个容纳多个线程的容器，池中的线程可以被重复使用，从而避免了频繁创建和销毁线程的操作，提高了性能。

7.1 线程池的好处

  • 降低资源消耗：线程池避免了频繁创建和销毁线程，节省了系统资源。
  • 提高响应速度：线程池中的线程可以被复用，从而减少了线程创建的时间，提升了任务响应速度。
  • 提高线程管理性：线程池可以统一管理线程，控制最大线程数，并且可以通过 ExecutorService 提供的多种配置来优化线程池的使用。

7.2 Java 中的四种线程池类型

7.2.1 缓存线程池（newCachedThreadPool()）
  • 特点：线程池的线程数是无限制的，线程池会根据需要创建新线程，如果线程空闲超过 60 秒则会被回收。
  • 适用场景：适合于处理大量短期异步任务。
7.2.2 固定大小线程池（newFixedThreadPool()）
  • 特点：线程池大小固定，适用于需要并发执行固定数量任务的场景。
  • 适用场景：适合任务量大且任务执行时间较长的场景。
7.2.3 单线程池（newSingleThreadExecutor()）
  • 特点：只有一个线程执行所有任务，任务按顺序执行。
  • 适用场景：适用于任务需要按顺序执行的场景，确保任务依次执行。
7.2.4 周期性任务线程池（newScheduledThreadPool()）
  • 特点：支持定时任务和周期性任务，可以按照固定的时间间隔执行任务。
  • 适用场景：适用于需要周期性执行的任务，例如定时任务、日志定期清理等。

7.3 线程池的配置与管理

  • 核心线程数：线程池中始终保持的线程数量（即使这些线程处于空闲状态）。
  • 最大线程数：线程池中允许的最大线程数量。
  • 空闲线程的存活时间：超过一定时间没有任务执行的线程将被销毁。
  • 工作队列：用于存放待执行任务的队列，线程池中的任务会从这个队列中获取。

7.4 线程池的优势

  • 复用线程：减少线程创建和销毁的开销，提高系统性能。
  • 灵活管理：通过配置线程池的大小和任务队列，优化并发任务的执行。
  • 任务调度：支持定时和周期性任务，适用于需要定时执行的任务。
