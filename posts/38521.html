字符串的 StringBuffer 和 StringBuilder

在 Java 中，String 是不可变的（immutable），这意味着每次对字符串进行修改都会创建一个新的对象。为了提高字符串操作的效率，Java 提供了 StringBuffer 和 StringBuilder，它们是可变的字符串类，适用于频繁修改字符串的场景。

StringBuffer

StringBuffer 是线程安全的（synchronized），适用于多线程环境。

  • delete(int start, int end): 删除指定范围内的字符串
  • reverse(): 反转字符串
  • toString(): 将 StringBuffer 转换为 String

什么时候使用 String、StringBuffer、StringBuilder？
  • 使用 String：当字符串不会被修改时，例如存储不可变的文本内容。
  • 使用 StringBuffer：在多线程环境下，字符串需要被频繁修改时。

7.List系列

类似于Python中的列表。

List是一个接口，接口下面有两个常见的类型（目的是可以存放动态的多个数据）

Java 中的 Arrays 数组和 List（例如 ArrayList）是两种不同的数据结构，各自有不同的优点和用途。虽然它们都可以存储多个元素，但它们在使用方式、灵活性、性能等方面有所区别，因此在 Java 中会根据不同的场景选择使用 Arrays 数组还是 List。

主要区别与选择依据
特性数组（Arrays）List（如 ArrayList）
大小固定大小，初始化时必须指定长度，之后不能改变大小。动态大小，可以随时添加或删除元素。
元素类型可以是基本数据类型（如 int, char 等）或引用类型（如 String）。只能存储对象类型（引用类型），不能存储基本数据类型。
性能访问元素速度非常快，因为底层是连续的内存空间。访问元素时相对较慢，底层实现是链表或动态数组，可能涉及更多的内存操作。
存储类型不支持泛型，但可以存储基本数据类型（如 int[], double[]）。只能存储对象类型，支持泛型（如 ArrayList<Integer>）。
操作灵活性对数组的操作（如增加、删除元素）比较麻烦，需要自己手动处理。提供了很多内置方法（如 add()、remove()、get()、set()）来操作元素。
线程安全数组本身是线程不安全的，访问时需要自己处理同步。ArrayList 本身也不是线程安全的，但可以通过 Collections.synchronizedList 或 CopyOnWriteArrayList 来处理线程安全问题。
  • ArrayList，连续的内存地址的存储（内部自动扩容）。 -> Python列表的特点
  • LinkedList，底层基于链表实现（自行车链条）。 -> Python列表的特点

Integer 类详解

Integer 类是 Java 中的一个包装类，属于 java.lang 包，它封装了一个基本数据类型 int 的值。Integer 类是 Number 类的子类，继承了 Number 类中的各种方法，并为 int 提供了更多的功能。Integer 类实现了 Comparable<Integer> 接口，因此它的对象可以进行排序。

1. 构造方法

Integer 类提供了几个常用的构造方法：

  • Integer(int value)：使用指定的 int 值创建一个 Integer 对象。
  • Integer(String s)：使用字符串 s 创建一个 Integer 对象，字符串必须能够解析为一个整数。
2. 常量定义

Integer 类提供了一些常量来表示特定的整数值范围：

  • Integer.MAX_VALUE：int 类型的最大值，即 2^31 - 1，值为 2147483647。
  • Integer.MIN_VALUE：int 类型的最小值，即 -2^31，值为 -2147483648。
  • Integer.SIZE：int 类型的位数，值为 32。
  • Integer.BYTES：int 类型的字节数，值为 4。
3. 常用方法

Integer 类提供了许多常用方法，帮助我们对整数进行操作：

  • intValue()：返回 Integer 对象的 int 值。
  • compareTo(Integer anotherInteger)：与另一个 Integer 对象进行比较，返回一个整数，表示大小关系。
  • equals(Object obj)：比较两个 Integer 对象的值是否相等。
  • parseInt(String s)：将字符串 s 解析为一个 int 值。
  • toString()：返回 Integer 对象的字符串表示。
  • valueOf(int i)：返回一个包含指定 int 值的 Integer 对象。
  • toBinaryString(int i)：返回整数 i 的二进制表示（字符串形式）。
4. 自动装箱与自动拆箱

Java 支持 Integer 类的自动装箱和自动拆箱。装箱是指将基本类型 int 转换为 Integer 对象，而拆箱是指将 Integer 对象转换为 int 值。

5. 常见的静态方法

Integer 类中有几个静态方法，帮助我们进行整数和字符串之间的转换或处理：

  • Integer.parseInt(String s)：将字符串 s 转换为 int 类型。
  • Integer.valueOf(String s)：将字符串 s 转换为 Integer 对象。
  • Integer.toBinaryString(int i)：返回 i 的二进制字符串。
  • Integer.toHexString(int i)：返回 i 的十六进制字符串。
  • Integer.toOctalString(int i)：返回 i 的八进制字符串
6. 使用 Integer 的好处
  1. 与集合兼容：基本类型 int 不能存储在集合框架中，但 Integer 作为对象可以被轻松存储在集合中，如 ArrayList<Integer>。
  2. 比较大小：Integer 类实现了 Comparable<Integer> 接口，可以方便地进行比较。
  3. 对象特性：作为对象，Integer 可以与其他对象一样在方法中传递，支持各种对象的操作（例如调用方法）。

8.Set系列

Set是一个接口，常见实现这个接口的有两个类，用于实现不重复的多元素集合。

  • HashSet，去重，无序。
  • TreeSet，去重，内部默认排序（ascii、unicode）【不同的数据类型，无法进行比较】。

Set 接口是 Java 集合框架的一部分，它用于存储不重复的元素。常见的实现类包括 HashSet 和 TreeSet，其中 HashSet 是基于哈希表实现的，元素无序，而 TreeSet 是基于红黑树实现的，元素会按自然顺序排序。Set 接口提供了一些常用方法，以下是这些方法的简要说明和示例。

5、运算符

算术表达式的注意点

& 运算符有两种用法：

  1. 按位与
  2. 逻辑与

&& 运算符是 短路与运算。

逻辑与 和 短路与 的差别：

  • 逻辑与：二者都要求运算符两侧的布尔值都为 true，整个表达式的值才是 true。
  • 短路与（&&）：如果左侧表达式的值为 false，右侧表达式会被直接短路，不再计算。

注意：
逻辑或运算符（|）和短路或运算符（||）之间的差别也是类似的。

6、关键字

1. Java 有没有 goto？

goto 是 Java 中的保留字，但没有被实际使用，不能用于控制流程。

2. final 关键字的作用

final 关键字可以用于修饰类、方法和变量：

  • 修饰类：表示该类不能被继承。
  • 修饰方法：表示该方法不能被子类重写。
  • 修饰变量：表示该变量是常量，不能被重新赋值（但如果是引用类型，引用指向的对象内容仍然可以改变）。

3. final、finally、finalize 的区别

  • final：用于修饰类、变量、方法，表示不可变或不可继承/重写。
  • finally：通常用于 try-catch-finally 代码块，表示无论是否发生异常，该代码块都会执行（用于释放资源）。
  • finalize：是 Object 类的方法，在垃圾回收前由 GC 线程调用，进行对象清理工作（不建议依赖该方法，已被废弃）。

7. static 关键字的作用

static 关键字的主要作用是创建独立于实例对象的变量或方法，即：

  • 静态变量：属于类，而不是实例对象，所有对象共享该变量。
  • 静态方法：可以直接通过类名调用，而不需要创建对象。
  • 静态代码块：用于在类加载时执行一次初始化操作。

8. static 的独特之处

  • 静态变量/方法属于类，而不是实例对象。
  • 类加载时执行，并且只执行一次。
  • 静态方法只能访问静态成员（不能访问非 static 变量）。
  • static 代码块优先于构造函数执行。
  • 不能在 static 环境中使用 this 和 super。

9. static 的应用场景

  • 修饰成员变量（所有实例共享变量）
  • 修饰成员方法（工具方法）
  • 静态代码块（类加载时初始化）
  • 修饰内部类（静态内部类）
  • 静态导包（import static 用于导入静态方法/变量）

10. static 使用的注意事项

  1. 静态方法不能访问非静态成员（因为静态方法属于类，而非对象）。
  2. static 变量在类加载时初始化，而不是在实例创建时。
  3. 多个对象共享 static 变量（不同实例修改 static 变量，会影响所有对象）。
  4. static 代码块只执行一次（在类加载时执行）。
  5. 不能在 static 方法中使用 this 和 super。
