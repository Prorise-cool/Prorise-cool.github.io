Junit 是 Java 的一个单元测试框架，用于确保单独方法或类的正确性。通过运行测试方法，它帮助开发人员检查代码是否按预期工作。

第二章 类的加载时机

1. 类加载时机

类的加载时机可以在以下几种情况下发生：

  1. 创建新对象：通过 new 关键字创建对象时，类会被加载到内存。
  2. 创建子类对象：当创建一个子类对象时，父类会先被加载。
  3. 执行 main 方法：启动 Java 应用程序时，main 方法所在的类会被加载。
  4. 调用静态成员：当访问类的静态成员（变量或方法）时，类会被加载。
  5. 反射，创建 Class 对象：通过反射机制调用 Class.forName() 或 getClass() 等方法时，类会被加载。

2. 类加载器（了解）_ClassLoader

ClassLoader 是 JVM 中的一个对象，负责将本地磁盘上的 .class 文件加载到内存中，形成 Class 对象。

2) 分类

ClassLoader 根据加载的类的来源不同，分为以下几种类型：

  • BootStrapClassLoader（引导类加载器）：负责加载核心类库，使用 C 语言编写，因此我们无法直接访问它。它加载的类包括 System、String 等类，存放在 jre/lib/rt.jar 中。

  • ExtClassLoader（扩展类加载器）：负责加载 JDK 的扩展类库，主要加载 jre/lib/ext 目录下的类。

  • AppClassLoader（系统类加载器）：负责加载应用程序自定义的类或通过 java -cp 指定的类，通常加载在 classpath 下的类和第三方 JAR 包。

3) 三者关系

从类加载机制的层面上看，AppClassLoader 的父类加载器是 ExtClassLoader，而 ExtClassLoader 的父类加载器是 BootStrapClassLoader。然而，从代码级别看，它们之间并没有继承关系，都是 ClassLoader 的实例。

4) 获取类加载器对象

可以通过 Class 对象的 getClassLoader() 方法来获取该类的加载器。

5) 获取类加载器的父加载器

通过 getParent() 方法，可以获取该类加载器的父加载器。

6) 双亲委派机制

双亲委派机制是指，当子类加载器需要加载某个类时，它会先请求父类加载器加载该类。如果父类加载器无法加载，再由当前加载器加载。

7) 类加载器的缓存机制

类加载器有一个缓存机制，即一旦加载某个类后，该类会被缓存到内存中。下次再访问该类时，会直接从缓存中返回，而不会重新加载。这样可以保证类在内存中的唯一性。

第三章 反射

反射是一种通过分析和操作类及其成员（如字段、方法、构造方法等）的一种技术。它允许程序在运行时动态地获取类的信息，并且可以访问和修改类的属性和方法。反射机制在许多框架和工具中都有广泛应用，如 Spring、Hibernate 等。

反射的好处

使用反射的主要好处是能够使代码更加通用和灵活。通过反射，我们可以在不知道具体类的情况下，动态地调用其方法、访问字段和创建对象。这使得程序能够更容易扩展和维护，特别是在处理不同类型的对象时。

如何学习反射

  • 将反射看作是一套 API 来学习：理解 Java 中反射机制的核心 API，如 Class 类、Method 类、Field 类等，掌握它们如何帮助操作类的结构。

第四章 注解

Annotation 简介

  • Annotation（注解） 是 Java 5 引入的一种元编程机制，可以用来 减少程序配置代码，并在编译时、运行时提供额外的 元信息（Metadata）。

主要作用：

  1. 编译时检查（如 @Override）。
  2. 运行时反射读取（如 @Deprecated）。
  3. 减少 XML 配置（如 Spring Boot 的 @Component，@Service）。
  4. 代码生成（如 Lombok 的 @Data 自动生成 getter/setter）。

准确覆写 @Override

  • @Override 注解 用于明确表示子类正在覆写父类的方法，能够在编译阶段检查错误。

作用：

  • 确保方法正确覆写：方法名拼写错误或参数不匹配时，编译器会报错。
  • 增强代码可读性：清楚地标明该方法是来自父类或接口的重写。

示例：使用 @Override

过期声明 @Deprecated

  • @Deprecated 注解 用于标记不推荐使用的类、方法或字段，尽管它们依然可以使用，但会触发警告。

作用：

  • 提示开发者：该方法或类已经过时，不建议继续使用。
  • 提供新方案：可以在 @Deprecated 的 JavaDoc 中说明替代方案。

示例：使用 @Deprecated

编译时警告信息：

若不希望看到此警告，可以使用 @SuppressWarnings("deprecation")。

压制警告 @SuppressWarnings

  • @SuppressWarnings 注解 用于抑制编译器警告，防止无关紧要的警告干扰开发。

作用：

  • 避免不必要的警告，如 @Deprecated 方法的调用、未使用的变量、泛型类型检查等。
  • 提高代码整洁度，但要谨慎使用，避免隐藏潜在问题。

常见的 @SuppressWarnings 参数：

参数作用
"deprecation"隐藏 @Deprecated 相关的警告
"unchecked"隐藏泛型（如 List rawList = new ArrayList();）的警告
"rawtypes"隐藏未指定泛型类型的警告
"unused"隐藏变量未使用的警告

示例：使用 @SuppressWarnings

总结

注解作用适用范围
@Override确保方法正确覆写，防止拼写错误方法
@Deprecated标记过时的方法或类，提醒开发者不要使用方法、类、字段
@SuppressWarnings抑制编译器警告，防止不必要的警告干扰开发变量、方法、类

@SuppressWarnings 主要用于隐藏编译器警告，但要谨慎使用，避免隐藏潜在错误。

    • RetentionPolicy.RUNTIME：表示注解会在运行时保留，可以通过反射读取。

第五章.枚举

枚举（Enumeration）是 Java 语言中的一种数据类型，用于表示一组有限的、固定的常量集合。自 JDK 1.5 引入后，枚举成为了一种强类型的多例设计模式，使代码更加安全、可读和可维护。

1. 枚举的定义

枚举类用于定义有限个数的对象，每个枚举值都是该枚举类的实例。它通常用于表示固定的状态、选项或类别。

1.1 基本定义

使用 enum 关键字来定义枚举：

在 enum 中，枚举值 默认是 public、static、final，可以直接通过类名访问，例如 Color.RED。

2. 枚举与 Enum 类

Java 的 enum 关键字定义的类默认继承 java.lang.Enum 类，因此不能再继承其他类（Java 只支持单继承）。但可以实现接口。

每个枚举值都有一个默认的 ordinal() 方法，表示它的序号（从 0 开始）。

3. 枚举类的构造方法

可以给枚举类定义属性、构造方法，使每个枚举值具有额外的信息。

3.1 带参数的枚举

构造方法必须是 私有的（private），防止外部实例化。

  • 每个枚举常量调用构造方法时会传递参数。
