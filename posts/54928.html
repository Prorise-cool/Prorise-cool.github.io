    七、JAVA8新特性总结

    1. Lambda 表达式

    Lambda 表达式是 Java 8 引入的一个新特性，它让 Java 支持函数式编程风格。通过 Lambda 表达式，你可以更简洁地表示函数式接口的实例，简化代码结构。

    Lambda 表达式是匿名方法，它不同于内部类。Lambda 编译后只有一个 class 文件，而内部类编译后会有两个文件。Lambda 依赖 JVM 中的底层 API 来实现。

    2）Lambda 表达式语法

    Lambda 表达式的基本语法包含三部分：参数列表、箭头符号 -> 和 函数体。

    语法示例：

    • (int x, int y) -> x + y：接收两个整型参数并返回它们的和。
    • () -> 42：不接收任何参数，返回整数 42。
    • (String s) -> { System.out.println(s); }：接收一个字符串并打印。

    方法引用

    方法引用是 Lambda 表达式的简写形式，通过引用已有的方法来代替 Lambda 表达式，通常用于简化代码。

    方法引用使用 :: 符号，有四种常见形式：

    方法引用类型说明示例代码
    引用静态方法引用类中的静态方法String::valueOf，等价于 (s) -> String.valueOf(s)
    引用特定对象的实例方法引用某个对象的实例方法x::toString，等价于 () -> this.toString()
    引用特定类型的任意对象的实例方法引用某个类型的任意对象的实例方法String::toString，等价于 (s) -> s.toString()
    引用构造函数引用类的构造函数Person::new，等价于 () -> new Person()

    2.Stream API

    Stream API 是 Java 8 引入的一种函数式编程风格的数据处理工具，旨在简化集合操作。通过流可以实现：

    • 不修改原数据源
    • 链式操作，支持懒执行
    • 可串行或并行处理
    • 更简洁、高效的代码

    流的操作分类

    为什么需要 .collect()？

    流的 中间操作（如 filter、map 等）返回的依然是一个流（Stream 对象），而不是最终的集合或者结果。因此，你需要调用一个终端操作，通常是 .collect()，来执行流的操作并得到一个具体的结果（如 List、Set 等集合类型）。

    collect() 方法就是将流中的元素“收集”到一个集合（如 List、Set 等）中，或者进行其他类似的聚合操作。

    3. 接口的兼容性变动

    在 Java 8 之前，接口中的方法默认是抽象方法（没有方法体），实现类必须实现这些方法。然而，从 Java 8 开始，接口支持定义默认方法（default 方法）和静态方法（static 方法）。

    默认方法（default 方法）

    • 定义方式：使用 default 关键字来定义一个方法，并且可以为其提供默认实现。
    • 调用方式：默认方法可以通过实现接口的类实例化的对象来调用。
    • 作用：可以为接口的方法提供默认实现，避免强制实现类每次都实现接口中的每个方法。

    类方法（静态方法，static 方法）

    • 定义方式：使用 static 关键字来定义静态方法，属于接口本身，不是实例的方法。
    • 调用方式：类方法只能在本接口中调用，或者通过接口名直接调用，不能通过实现类的实例来调用。
    • 作用：静态方法不需要对象实例化即可调用，且不能被实例化对象覆盖。

    4. 函数式接口

    1. 函数式接口的定义

    函数式接口是一个接口，它有且仅有一个抽象方法。可以有多个默认方法（default）和静态方法（static）。函数式接口可以隐式转换为 Lambda 表达式，常用于支持函数式编程。

    关键特点：

    • 只能有一个抽象方法：每个 Lambda 表达式都会被匹配到这个抽象方法。
    • 可以有多个非抽象方法：包括 default 方法和静态方法。
    • @FunctionalInterface 注解是可选的，但是使用它可以明确标识该接口是函数式接口。

    2. 常见的函数式接口和方法

    UnaryOperator<T>接受一个参数并返回一个相同类型的结果T apply(T t)：返回与输入类型相同的结果
    BinaryOperator<T>接受两个相同类型的参数，返回一个结果T apply(T t, T u)：接受两个相同类型的参数并返回一个结果

    5.Optional容器类

    Optional<T> 是 Java 8 引入的一个容器类，用来避免 null 值引起的 NullPointerException。它提供了一些方法来显式地检查、操作和转换可能为 null 的对象，目的是使代码更具可读性和健壮性。

    方法概览

    方法说明
    ofNullable(T value)返回一个可能为 null 的 Optional 对象。
    of(T value)返回一个非 null 的 Optional 对象。若值为 null 会抛出异常。
    ifPresent(Consumer<? super T> action)如果值存在，执行指定的动作。
    get()获取值，如果值为空抛出 NoSuchElementException。
    orElse(T other)如果值为 null，返回指定的默认值。
    orElseGet(Supplier<? extends T> other)如果值为 null，返回由给定的 Supplier 提供的值。
    orElseThrow(Supplier<? extends X> exceptionSupplier)如果值为 null，抛出异常。
    map(Function<? super T, ? extends U> mapper)如果值存在，应用转换函数。
    flatMap(Function<? super T, Optional<U>> mapper)如果值存在，应用转换函数，返回 Optional 类型。
    filter(Predicate<? super T> predicate)如果值存在且满足给定条件，返回该值，否则返回空 Optional。
    stream()将 Optional 转换为 Stream。

    常用场景

    1. 判空检查：避免显式使用 null 检查，提高代码可读性。
    2. 默认值处理：当值可能为空时，提供默认值以避免空指针异常。
    3. 懒加载：在需要时才计算默认值，避免不必要的计算。
    4. 链式操作：通过 map 和 flatMap 对值进行转换。
    5. 流式处理：将 Optional 转换为 Stream，便于处理和聚合。

    7，新工具 − 新的编译工具

    Nashorn JavaScript 引擎

    Nashorn 是 Java 8 引入的轻量级、高性能 JavaScript 引擎，作为 Rhino（旧版本 JavaScript 引擎）的替代者。它允许在 JVM 上运行 JavaScript 代码，提供了更好的性能和与 Java 的集成能力。

    • 取代 Rhino：Nashorn 替代了 JDK 1.6 和 JDK 1.7 中的 Rhino 引擎，成为 Java 的嵌入式 JavaScript 引擎。
    • 性能提升：通过使用 JDK 7 中引入的 invokedynamic，将 JavaScript 编译成 Java 字节码，Nashorn 提供了比 Rhino 更高的性能，性能提升为 2 到 10 倍。
    • 支持 ECMAScript 5.1：Nashorn 完全支持 ECMAScript 5.1 规范，并且包括一些扩展功能。
    • Android 开发：Nashorn 主要用于 Android 的混合开发场景中，可以在 Android 应用中嵌入 JavaScript 代码并与 Java 代码进行交互。

    jjs — Nashorn 命令行工具

    jjs 是一个基于 Nashorn 引擎的命令行工具，可以直接执行 JavaScript 代码。它接受 JavaScript 源代码作为参数并执行。

    常见用途

    • 执行 JavaScript 脚本。
    • 可以通过命令行在 JVM 上快速执行 JS 代码。
    • 用于调试和测试 JavaScript 与 Java 交互的场景。

    8，新增base64加解密API

    Base64 编解码 API

    Java 8 中引入了 Base64 编码和解码功能，成为 Java 类库的标准。Base64 用于将二进制数据编码为 ASCII 字符串格式，通常用于数据传输和存储。Java 8 的 Base64 提供了三种编码方案：

    1. 基本型（Basic）：输出映射为一组字符 A-Za-z0-9+/，不添加任何行分隔符，解码时仅支持 A-Za-z0-9+/。
    2. URL 型（URL and Filename）：输出映射为一组字符 A-Za-z0-9+_，适合在 URL 和文件名中使用。
    3. MIME 型（MIME）：输出采用 MIME 友好格式，每行最多 76 字符，行之间使用 \r\n 作为分隔符。

    内嵌类

    内嵌类描述
    Base64.Decoder解码器，用于使用 Base64 编码解码字节数据。
    Base64.Encoder编码器，用于将字节数据编码为 Base64 格式。

    常用方法

    方法名描述
    static Base64.Decoder getDecoder()返回一个解码器，使用基本型 Base64 编码方案进行解码。
    static Base64.Encoder getEncoder()返回一个编码器，使用基本型 Base64 编码方案进行编码。
    static Base64.Decoder getMimeDecoder()返回一个解码器，使用 MIME 型 Base64 编码方案进行解码。
    static Base64.Encoder getMimeEncoder()返回一个编码器，使用 MIME 型 Base64 编码方案进行编码。
    static Base64.Encoder getMimeEncoder(int lineLength, byte[] lineSeparator)返回一个编码器，使用 MIME 型 Base64 编码方案，可以指定每行的长度和行分隔符。
    static Base64.Decoder getUrlDecoder()返回一个解码器，使用 URL 和文件名安全型 Base64 编码方案进行解码。
    static Base64.Encoder getUrlEncoder()返回一个编码器，使用 URL 和文件名安全型 Base64 编码方案进行编码。
